# Backlog Guide

## Purpose

- Track unfinished engineering work, follow-up plans, and implementation backlog for CSI.

## Ownership

- `README.md` backlog index.
- Current active plan and backlog documents in this folder.

## Local Contracts

- Keep only work that is still open, deferred, or awaiting manual verification.
- Delete or rewrite completed phases instead of preserving stale status history.
- Clearly separate current behavior references from proposed future changes.
- Link to current source files or current docs when a backlog item depends on a contract.

## Work Guidance

- Prefer a small number of current backlog docs over many superseded plan snapshots.
- Group items by active problem area and keep acceptance criteria actionable.
- When a design has shipped, move the durable contract to `../docs/` or `../Wiki/` and remove it from here.

## Verification

- Check links and source references.
- Confirm that each item here is still open before keeping it.
